# G2.1 – SAO LƯU GOOGLE DRIVE MIỄN PHÍ (1 LẦN/THÁNG)

## Mô hình

Web Lương/Supabase tạo snapshot dữ liệu các bảng `public` → Edge Function nén gzip và tính SHA-256 → Google Apps Script Web App → `DriveApp` lưu vào Google Drive của `tckt@thptvietau.edu.vn`.

- Không cần Google Cloud Project, OAuth Client ID/Secret, Service Account hoặc Google Cloud Billing.
- Dùng Google Apps Script và dung lượng Drive sẵn có.
- Lịch tự động: ngày 01 hằng tháng, khoảng 23:00, múi giờ `Asia/Ho_Chi_Minh`.
- Super Admin có thể chạy thủ công từ Web Lương.
- Tệp: `VIET-AU-PAYROLL-BACKUP-YYYY-MM.json.gz`.
- Tệp cùng tháng được thay thế bằng bản mới sau khi bản mới đã được tạo thành công.

## A. SQL – chạy một lần

1. Mở Supabase Dashboard đúng project Web Lương.
2. Vào **SQL Editor → New query**.
3. Mở file `supabase/migrations/20261102_system_drive_backup_monthly.sql` trong gói này, copy toàn bộ và dán vào SQL Editor.
4. Nhấn **Run**. Chỉ chạy một lần; không chạy lại nếu đã thành công.
5. Xác nhận bảng `public.system_backup_runs` xuất hiện trong Database → Tables.

Migration chỉ thêm bảng lịch sử và RPC snapshot; không sửa bảng nghiệp vụ lương, công thức hoặc dữ liệu nhân sự.

## B. Cập nhật Google Apps Script đang dùng gửi phiếu lương

**Không tạo project Apps Script mới.** Dùng chính project đang chạy cổng gửi email phiếu lương để giữ nguyên endpoint hiện tại và chức năng email.

1. Đăng nhập Google bằng `tckt@thptvietau.edu.vn`, mở project Apps Script hiện đang dùng gửi phiếu lương.
2. Trong file `Code.gs`, thay nội dung bằng toàn bộ file `supabase/apps-script/Code.gs` trong gói này. File mới giữ nguyên luồng `PAYROLL_EMAIL_TOKEN` và `GmailApp.sendEmail`, đồng thời bổ sung nhánh nhận backup.
3. Mở **Project Settings → Script Properties**, giữ nguyên `PAYROLL_EMAIL_TOKEN` hiện tại và thêm:

| Property | Value |
|---|---|
| `BACKUP_SECRET` | Một chuỗi bí mật dài, tự tạo, tối thiểu 32 ký tự |
| `SUPABASE_FUNCTION_URL` | `https://<PROJECT_REF>.supabase.co/functions/v1/system-drive-backup` |
| `SUPABASE_ANON_KEY` | Publishable/anon key của đúng project Supabase |

`BACKUP_SECRET` sẽ được dùng giống hệt trong Supabase Secrets ở bước C. Không gửi giá trị bí mật qua chat và không đưa vào GitHub.

4. Vào **Project Settings → Time zone**, chọn `Asia/Ho_Chi_Minh`.
5. Chọn **Deploy → Manage deployments → Edit** deployment Web App hiện có, chọn **New version**, giữ nguyên:
   - Execute as: **Me**
   - Who has access: **Anyone** (nếu chính sách Google Workspace cho phép)
6. Deploy. Giữ nguyên URL Web App đang được ứng dụng gửi phiếu lương sử dụng.
7. Chạy hàm `setupMonthlyBackup` một lần trong Apps Script Editor. Cấp quyền Drive và UrlFetch khi Google yêu cầu. Hàm tạo thư mục `VIET AU PAYROLL BACKUP` và trigger ngày 01 hằng tháng lúc khoảng 23:00.
8. Chạy `testBackupGateway` để xác nhận script truy cập được thư mục Drive. Đây chỉ là kiểm tra thư mục, chưa tạo bản backup.

## C. Supabase Edge Function

1. Vào Supabase → **Project Settings → Edge Functions → Secrets** (hoặc Edge Functions → Secrets).
2. Thêm 2 Secrets:

| Secret | Value |
|---|---|
| `GOOGLE_APPS_SCRIPT_URL` | URL Web App ở bước B |
| `BACKUP_SECRET` | Đúng chuỗi `BACKUP_SECRET` đã lưu trong Apps Script |

`SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY` là biến hệ thống có sẵn trong Edge Functions; không tạo bản sao nếu Supabase đã cấp tự động.

3. Vào **Edge Functions**, tạo function tên chính xác `system-drive-backup`.
4. Dán toàn bộ nội dung file `supabase/functions/system-drive-backup/index.ts` trong gói này và Deploy.
5. Với function này, tắt tùy chọn **Verify JWT** ở gateway. Lý do: lịch tháng gọi bằng `BACKUP_SECRET`, còn thao tác thủ công được function tự xác thực JWT và kiểm tra `system_is_admin()` trước khi chạy. Không bỏ bước xác thực bên trong function.

## D. Kiểm tra backup đầu tiên

1. Đăng nhập Web Lương bằng tài khoản SUPER ADMIN.
2. Vào **Quản lý hệ thống → Sao lưu Google Drive**.
3. Nhấn **Sao lưu ngay** và xác nhận.
4. Kiểm tra trạng thái SUCCESS trong giao diện, bảng `system_backup_runs` và thư mục Drive `VIET AU PAYROLL BACKUP`.
5. Tải tệp `.json.gz` về máy, thử giải nén để xác nhận file gzip hợp lệ.

Sau lần chạy thủ công thành công, trigger Apps Script sẽ tự chạy vào ngày 01 hằng tháng. Không chạy `scheduledBackup()` thủ công; nếu muốn thử lịch, hãy dùng nút **Sao lưu ngay** trong Web Lương.

## E. Bảo mật và phạm vi

- Chỉ SUPER ADMIN được chạy backup thủ công và xem lịch sử trên Web Lương.
- Apps Script lưu file bằng quyền Drive của tài khoản triển khai `tckt@thptvietau.edu.vn`.
- `BACKUP_SECRET` là khóa nội bộ giữa Apps Script và Edge Function. Bảo vệ như mật khẩu.
- Snapshot gồm dữ liệu các bảng thuộc schema `public`.
- Không gồm `auth.users`/`auth.identities`, file nhị phân Supabase Storage, cấu hình hệ thống, database roles hoặc physical PostgreSQL dump.
- Đây là bản sao lưu dữ liệu logic, chưa phải tính năng khôi phục. Không dùng snapshot này để tự động ghi đè production.
- Dung lượng lớn có thể vượt giới hạn request/thời gian thực thi của Apps Script hoặc giới hạn phản hồi RPC. Khi đó function ghi FAILED và hiển thị lỗi; không được coi là backup thành công.

## F. Nếu gặp lỗi

- `BACKUP_ENVIRONMENT_NOT_CONFIGURED`: kiểm tra 2 Supabase Secrets và các biến môi trường mặc định của Edge Function.
- `BACKUP_UNAUTHORIZED`: hai giá trị `BACKUP_SECRET` không giống nhau.
- `BACKUP_FOLDER_NOT_INITIALIZED...`: chạy `setupMonthlyBackup()` một lần.
- `GOOGLE_APPS_SCRIPT_URL` lỗi/HTML thay vì JSON: kiểm tra Web App đã Deploy phiên bản mới, quyền truy cập Anyone và URL `/exec`.
- `SERVICE_ROLE_REQUIRED`: kiểm tra Edge Function gọi RPC bằng service-role key; không thay bằng anon key.
- `SUPER_ADMIN_REQUIRED`: tài khoản hiện tại không có role SUPER_ADMIN.
- `BACKUP_TOO_LARGE_FOR_APPS_SCRIPT_GATEWAY`: payload vượt giới hạn cổng Apps Script; không lặp lại liên tục, cần thiết kế chia phần riêng trước khi chạy lại.
