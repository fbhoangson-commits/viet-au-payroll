# G2.2 – Hoàn thiện các menu quản trị hệ thống

## Cơ sở mã nguồn
Được triển khai trên ZIP `viet-au-payroll-main (13).zip` do người dùng cung cấp.
Chỉ thay đổi các module quản trị hệ thống; không sửa công thức lương, dữ liệu lương,
`PayrollCalculationPage.jsx`, G1 hoặc luồng gửi phiếu lương.

## Các module trong gói
1. `connection-status`: kiểm tra Database, Storage, Auth, quyền Super Admin và Apps Script.
2. `data-restore`: đọc lịch sử backup, hiển thị metadata và checksum. Chưa thực hiện ghi/khôi phục dữ liệu production.
3. `email-settings`: hiển thị cấu hình gửi phiếu lương hiện có và kiểm tra phản hồi Apps Script. Không sửa token hoặc luồng gửi email.
4. `system-security`: hiển thị phiên, vai trò, trạng thái hồ sơ và các nhật ký quản trị gần đây.
5. `system-system-health`: Edge Function chỉ dành cho Super Admin, thực hiện health checks ở server; không trả secrets về trình duyệt.

## Triển khai

### A. Mã nguồn giao diện
1. Giải nén ZIP vào thư mục gốc dự án, giữ nguyên cấu trúc.
2. Commit và Push GitHub.
3. Chờ Cloudflare Pages deploy thành công.
4. Đăng nhập bằng tài khoản SUPER ADMIN và kiểm tra 4 menu.

### B. Edge Function mới
Tạo Function mới tên chính xác `system-system-health`.
- Source: `supabase/functions/system-system-health/index.ts`
- Verify JWT: BẬT (khác với function backup định kỳ).
- Deploy.
- Không thay đổi `system-drive-backup` đang hoạt động.
- Function dùng các biến hệ thống Supabase có sẵn và `GOOGLE_APPS_SCRIPT_URL` đã cấu hình trong Supabase Secrets.

### C. SQL
Không cần chạy SQL mới. Module dùng bảng `system_backup_runs`, `system_user_roles`,
`system_user_profiles`, `system_activity_logs` đã có trong các migration G1/G2.1.

## Phạm vi an toàn / giới hạn
- Khôi phục dữ liệu: chỉ đọc lịch sử và xem metadata. Không có nút giả lập phục hồi.
  Snapshot hiện tại không gồm auth.users, file bytes Storage hoặc physical PostgreSQL.
  Chưa có quy trình download từ Drive, schema compatibility check, transaction/rollback.
  Không được tự động ghi đè production khi chưa có các lớp bảo vệ này.
- Cấu hình email: chế độ giám sát chỉ đọc. Tài khoản gửi hiện tại là
  `tckt@thptvietau.edu.vn`, tên hiển thị PHÒNG TÀI CHÍNH. Không thay token,
  không thay endpoint và không đổi Apps Script gửi phiếu lương.
- Trạng thái kết nối: kiểm tra tại thời điểm người dùng bấm nút; không phải giám sát liên tục.
- Bảo mật: bảng kiểm tra quản trị, không phải penetration test.

## Kiểm tra sau deploy
1. Trạng thái kết nối → Kiểm tra lại; Database, Storage, Auth, Authorization và Apps Script mong đợi OK.
2. Khôi phục dữ liệu → thấy lịch sử backup; chưa có thao tác phục hồi.
3. Cấu hình email → Apps Script báo Hoạt động.
4. Bảo mật hệ thống → thấy email, vai trò SUPER ADMIN và audit log.
5. Đăng nhập tài khoản Kế toán → các menu quản trị này vẫn phải bị ẩn/chặn theo phân quyền hiện tại.
